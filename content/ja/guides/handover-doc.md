## 「整理して」が失敗する理由

同僚が退職しました。残ったのは、個人ノート12ページ、Excelファイル5つ、メールボックスで「発注」と検索した結果、そしてチームチャットで何か月も交わされた会話です。

これらをそのままAIに貼り付けて、「引き継ぎ文書として整理して」と入力します。AIは半日で見栄えのよい文書を返してきます。目次があり、項目ごとに分かれ、文章も滑らかです。問題は、実際に業務を始めた瞬間に表れます。月曜日に発注しようと文書を開くと、「誰の承認を得るのか」が書かれていません。決裁期限もありません。その代わり、資料のどこにもなかった「月次の定期点検をおすすめします」といった文が入り込んでいます。

AIは資料を**資料の種類ごとに**（ノートの要約、メールの要約、チャットの要約）整理しただけで、業務を**進める順番に沿って**整理したわけではありません。そして、抜けている部分を作り出して埋めてしまいます。引き継ぎ文書では、この二つが致命的になります。資料中心の構成では必要な情報を探せませんし、空欄が埋められていると、存在しない手順をそのまま実行してしまいます。

順番を逆にすればよいのです。資料から始めず、**質問から始めます**。新しい担当者が最初の1か月に検索しそうな質問を先に洗い出し、その質問に対して資料から根拠を見つけて答えを添えます。答えのない質問は「資料に記載なし」として残します。その一覧こそ、退職した人に本当に確認すべきこと、そして自分が直接確認すべきことになります。

## 機能するプロンプト

二段階に分けて使います。一度に実行すると、質問が資料に書かれている内容だけに引っ張られ、空欄が見えなくなります。

**1段階目 — 質問リストを抽出する**

```
以下は、退職した担当者が残した業務資料です。この業務を新しく担当する人が
最初の1か月に調べそうな質問を洗い出してください。

条件:
- 四つの領域に分けてください：①何をするのか（手順） ②誰とどのように連絡を取るのか（関係者） ③いつ、どのくらいの頻度で行うのか（スケジュール） ④問題が起きたらどこに相談するのか（対応）
- 「発注はどうやって行うの？」のように、実際に検索しそうな話し言葉で書いてください
- 資料に答えがなさそうな質問も含めてください。それが本当の空白です

資料:
"""
[ノート、メール、チャット記録を分けて貼り付ける]
"""
```

**2段階目 — 根拠のある答えを埋める**

```
以下の質問リストについて、添付した資料から根拠を見つけて答えを書いてください。

条件:
- 各回答の横に、根拠となった資料を [ノート]、[メール 3月14日] のように付けてください
- 資料に答えがない質問には、答えを作らず、「資料に記載なし」として残してください
- 答えが複数の資料にまたがる場合は、一つにまとめて手順の順番に沿って書いてください
- 最後に「資料に記載なし」の一覧を別にまとめてください

質問リストと資料:
"""
[1段階目で抽出した質問リスト＋資料を一緒に貼り付ける]
"""
```

なぜ二段階に分けるのでしょうか。1段階目で先に質問を抽出すると、AIは資料に書かれていることだけでなく、**書かれていないこと**も探すようになります。「資料に答えがなさそうな質問も含めてください」という条件がなければ、質問が資料にある内容に合わせられ、空欄がまったく見えなくなります。引き継ぎで最も危険なのは、空欄の存在に気づけない文書です。

2段階目の要は、根拠タグと「資料に記載なし」です。回答ごとに根拠が付いていれば、あとで確認するときに、どこから出た内容なのかすぐに確かめられます。「資料に記載なし」として残った項目は、退職者に送る質問リストであり、自分が直接確認する作業リストにもなります。空白を文書から消すのではなく、次にやることへ変えるわけです。

## 確認チェックリスト

返ってきた文書をそのままチームWikiに載せてはいけません。次の点だけ確認します。

- [ ] すべての回答に根拠タグが付いているか？（タグのない文章は、AIが補って書いたものです）
- [ ] 「資料に記載なし」の一覧を退職者に送ったか？（今聞かなければ、二度と確認できないかもしれません）
- [ ] 担当者・連絡先・頻度・期限が、実際の名前と数字で書かれているか？（「関係部署に確認」は答えではありません）
- [ ] 根拠となった原資料を、自分で一つずつ開いて確認したか？（AIが引用を誤って付けることもあります）
- [ ] この文書だけを見て、新しい担当者が最初の週の業務を実行できるか？

## 応用：退職する人があらかじめ作っておく

このプロンプトは、退職する人が事前に使うこともできます。条件を一つだけ変えます。

```
私がこの業務を離れたら、担当者が最初の1か月に調べそうな質問を30個洗い出してください。
私が残したノートと資料を確認し、資料に答えがない質問には[要確認]を付けてください。
```

事前に作っておけば、「資料に記載なし」となった項目を本人にすぐ確認できます。引き継ぎ文書の空白は残したままにせず、退職する時点で埋めるのがいちばん安上がりです。

## このプロンプトの限界

AIは、資料にない業務を知りません。どれほど上手に質問を洗い出しても、資料に答えがなければ「資料に記載なし」にしかなりません。それを埋めるのは、退職者との一本の電話や、取引先とのメール履歴の確認です。プロンプトは、この空白を**見えるようにする**だけです。

資料が古くなっている可能性も確認しなければなりません。昨年変更された決裁手順が、今年のノートに反映されていないかもしれません。根拠資料に日付があれば、回答の横にその日付も書かせ、1年以上前の根拠については、実際の担当者に現行の手順かどうかを確認します。

チャット履歴には、冗談と業務上のやり取りが混ざっています。AIが冗談を手順として整理してしまうこともあります。人名や部署名が出てくる回答は、すべて一度は自分で直接読んで確認してください。
