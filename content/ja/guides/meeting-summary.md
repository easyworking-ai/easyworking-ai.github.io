## 「要点だけまとめて」が失敗する理由

最もよく使われるプロンプトだ。そして最もよく失敗するプロンプトでもある。

会議が終わって議事録をAIに投げて「要点だけまとめて」と入力する。AIはきれいな要約を返してくれる。問題はその要約をチームメンバーに送った時に始まる。「この決定はいつされたの？」「誰がやることになった？」「期限が抜けてるね」。AIが選んだ「要点」とチームが必要としている「要点」が違うからだ。

AIは文章の中から「重要そうな」文を選ぶ。しかし議事録で重要なのは文ではなく**決定・担当者・期限・次のステップ**だ。この4つを明示的に抽出しなければ、要約はきれいだが使い物にならない。

## 動くプロンプト

以下のプロンプトを議事録テキストの前に付けて送る。引用符内の議事録を実際の内容に差し替えればいい。

```
以下の議事録を以下の形式で整理してください。

1. 会議情報（日付、参加者、テーマ）
2. 議論した議題（1行ずつ）
3. 決定事項（誰が、何を、いつまでに）
4. 保留事項（次回会議で議論）
5. 次回会議日程

議事録:
"""
[ここに議事録を貼り付け]
"""
```

このプロンプトが「要点だけまとめて」と違う点は3つある。

第一に、**抽出する項目を指定した**。AIが「重要そうなもの」を選ぶのではなく、決定・担当者・期限を構造的に抽出する。

第二に、**形式を固定した**。1番から5番まで番号があり、各項目に入る内容が決まっている。チームメンバーが要約を受け取った時、どこで何を探すべきかわかる。

第三に、**保留事項を分離した**。会議で決定されなかったものを「決定事項」に混ぜない。これが意外に重要だ。「議論あり」と「決定あり」が混ざっていると、誰かが決定されたと思って実行に移してしまう。

## 検証チェックリスト

AIが返した要約をそのまま送らない。30秒だけ確認する。

- [ ] 決定事項ごとに担当者の名前があるか？
- [ ] 期限が明記されているか？（「早急に」は期限ではない）
- [ ] 保留事項が決定事項に混ざっていないか？
- [ ] 自分が会議で聞いた内容と要約に違う部分があるか？

最後の項目が最も重要だ。AIが間違って要約した部分は、自分が会議に出席しているからこそ発見できる。会議に出席していない人がこの要約を読んだら、間違った情報をそのまま信じていただろう。AIの要約を検証できる人が最後に一度確認することが必須だ。

## 応用：週次会議にまとめる

毎日議事録を整理すれば、金曜日に1週間分を一つにまとめられる。

```
以下は今週の議事録要約5つです。これを一つにまとめてください。

条件:
- 同じ議題が複数の会議で議論された場合、最後の決定だけ残して
- 期限が過ぎた項目は「完了」または「延期」で表示して
- 来週議論する議題だけ「保留」に残して

議事録要約:
"""
[月〜金の要約を順番に貼り付け]
"""
```

こうすれば月曜日の朝に「先週の決定事項」を1枚でチームに送れる。毎日送る要約は読まないチームメンバーも、週次要約は読む。

## このプロンプトの限界

議事録の品質が悪いとAIもできない。誰が発言したか書かれていなければ担当者を抽出できず、決定が書かれていなければ決定事項を作り出してしまう。AIが内容を推論して埋めるケースが最も危険だ。議事録自体がめちゃくちゃなら、プロンプトを直す前に議事録をどう記録するかから決めなければならない。

音声録音をAIに書き起こさせてからこのプロンプトを適用するのも方法だ。ただしこの場合、話者識別が正確でない可能性があるため、担当者部分は必ず人が確認する。
