## 長い文書が「読めたふり」をする理由

業務には長い文書が届きます。助成金の募集要項、提案依頼書、契約審査資料。全文を読む時間はないので、AIに丸ごと貼り付けて「この文書を読んで要約して」と入力します。

AIは要約を返します。ところが妙です。前半の概要は詳しいのに、肝心の支給要件やスケジュールなど中盤〜後半の内容は一文二文で雑に流される。回答のどこにも「どの部分にそう書いてある」という根拠がありません。

原因は二つあります。第一に、文書がAIが同じ比重で扱える量を超えています。分量としては入り込むように見えても、モデルは前半と後半に注意を向け、中盤を流し読みする傾向があります。第二に、質問が開いています。「要約して」はAI自身に何を重要と見るか選ばせるという意味で、その判断基準はあなたのものとは違います。

解決の方向は決まっています。文書を分割し、先に地図を作り、関連部分だけを読み直させ、根拠を報告させることです。

## 効くプロンプト

### ステップ1 — 文書の地図を作る

文書を章の区切りで4〜5等分します。各分割に下のプロンプトを実行します。「文書 (1/4)」の部分を変えて繰り返すだけです。

```
下の文書を要約せず、まず構造を掴んでください。

出力形式:
1. 文書の概要 — 何についての文書か2文で
2. 章の一覧 — タイトル、開始位置、扱うトピックを1行で
3. 私が最終的に知りたいことと最も関係の深い章を3つと、その理由

私が最終的に知りたいこと:
[例: 助成金の支給要件と申告締切、そして自社が要件に該当するか]

文書 (1/4):
"""
[章の区切りで分けた最初の部分]
"""
```

4回のやり取りが終わると、文書全体の地図が揃います。どの章に何があるのか、この時点で初めて分かります。

いくつかの細部が結果を分けます。「知りたいこと」は4分割すべてで同じ文で書きます。そうすれば各分割で選ばれた「関係の深い章3つ」を後でまとめて比較できます。開始位置はページ番号で書かせると、ステップ2で抜粋を再度開くとき文書の該当ページをすぐ開けます。ある分割だけ極端に長い場合は、無理に4等分せずその章をさらに細かく分けます。半端な章が混ざった地図は、後でたどるとき混乱を増やすだけです。

### ステップ2 — 関連部分だけを読み直して質問する

地図から質問に関係の深い章だけを選び、新しい会話に貼り付けます。

```
下記は文書の[第3章 支給条件]の部分だけを抜き出したものです。
この部分だけを根拠にして、質問に答えてください。

質問: 支給要件のうち、会社規模に関わる条件は何ですか?

条件:
- 回答ごとに根拠となる文を原文のまま引用してください
- この抜粋にない内容を聞かれたら「この部分にはない」と答えてください。推測で埋めないでください
- 条件が複数に分かれる場合は条件ごとに整理してください

文書の抜粋:
"""
[関連する章だけを貼り付け]
"""
```

このプロンプトが「読んで要約して」と違う点は三つです。

第一に、**読む範囲を狭めました**。文書全体ではなく、質問に関係する章だけを提示します。中盤の流し読み問題が消えます。

第二に、**根拠の引用を強制しました**。回答ごとに原文の文が付くので、後で文書を検索して検証できます。

第三に、**なければないと言わせました**。AIは質問を受けると何かを埋めようとする性質があります。「この部分にはない」を許可すると、でっち上げが目に見えて減ります。

質問は一度に一つずつ投げるのが良いです。三つまとめて聞くと、AIは境界を曖昧にした一塊の回答を返します。特に「要件」と「スケジュール」のように文書の別々の章に分かれているものが一つの回答に混ざると、後で引用を検証するとき、どの答えがどの章の根拠なのか振り分け直しになります。急ぐとかえって遅くなります。

新しい会話を始める理由も同じです。前の会話の要約や地図が残っていると、AIはその記憶を根拠として引き込みます。抜粋だけを根拠にさせるには、会話を空にして始めるのが確実です。

## 検証チェックリスト

- [ ] 引用された文を文書検索で直接確認したか? 見つからなければ架空の引用です
- [ ] 「この部分にはない」と出た項目が、別の章にないか地図を見直したか?
- [ ] 数字・日付・金額が引用原文と一致しているか?
- [ ] 関連章を選ぶとき、自分の質問の言い回しだけを信用していないか? 文書は別の用語を使うことがあります

## 応用: 2つの文書ドラフトの比較

改定案が出たら、地図を2組作って条項単位で比較します。

```
下記は同じ主題の2つの文書から[契約条件]の部分をそれぞれ抜き出したものです。
条項単位で比較してください。

出力形式:
1. 変更された条項 — 従来の文 → 変更後の文(文書に変更理由があれば一緒に)
2. 片方にしかない条項 — どちらにだけあるか
3. 同一の条項 — 条項番号のみ列挙

条件:
- 同一の条項もまとめず、番号で列挙してください。後で原本確認に使います
- どちらにもない条項は作らないでください

文書Aの抜粋:
"""
[現行案の該当部分]
"""

文書Bの抜粋:
"""
[改定案の該当部分]
"""
```

## このプロンプトの限界

分割の基準は人が決めます。章の区切りが明確な文書は簡単ですが、目次のないスキャン文書はどこで分けるかの判断から必要です。スキャン画像PDFなら、まずテキスト抽出が先で、抽出品質が悪いと以降の工程すべてが揺らぎます。

引用も間違えます。AIは存在しない文を引用らしく作り出します。だからチェックリストの最初の項目が引用検索です。そして探すものの定義が誤っていれば、地図も抜粋も誤った方向に進みます。読む速さが上がっただけで、何を探すかは引き続き人の仕事です。

分量の限界も現実的です。百ページの文書を五分割すれば、地図作りだけでやり取りが5回です。そこに抜粋での質問が2〜3回加わります。一度貼り付けて一度回答を得るのに比べると手間は増えます。その代わり回答には根拠が付くので、誤った結論を持って会議に入るリスクは減ります。十ページ程度で質問が一つなら、この手順は過剰です。丸ごと貼り付けて引用を要求するだけで十分です。
