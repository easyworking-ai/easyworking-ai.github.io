## 「賢いモデルに変えればいいですよね？」

エージェントが実務で問題を起こすと、最も先にすることはモデルを変えることだ。GPT-4oからClaudeへ、ClaudeからGeminiへ。プロンプトを磨き、温度を0に下げ、few-shot例を追加する。こうした試みの8割は失敗する。なぜなら問題の原因がモデルの知能ではなく**実行構造**にあるからだ。

ベンチマークスコアが高いモデルを使っても、エージェントは依然として途中で止まり、ツール呼び出しが失敗し、コストが制御不能になる。賢いモデルは「与えられた環境でより良い答えを出す」という意味であって、「環境自体の問題を解決する」という意味ではない。

ランタイム信頼性 — エージェントが一回だけ上手くいくのではなく継続して上手くいくようにするもの — を判断する5つの基準を整理する。

## 1. レイテンシ予算（Latency Budget）

エージェントが一つの作業を完了するのにどれくらいかかるか。シンプルな質問だが、ほとんどのチームがこれを測定していない。

エージェントが5ステップを経なければならない時、各ステップはモデル推論（3〜15秒）+ ツール呼び出し（1〜30秒）で構成される。5ステップなら最小20秒、最大200秒。ユーザーが待てる時間を超えると、途中で諦めるか手動で処理する。

実務で確認すべきは平均ではなく**最悪のケース**だ。P99レイテンシ（100回中1回のペースで発生する最も遅い応答）が5分なら、その1回のためにワークフロー全体が止まる。レイテンシ予算を設定し、それを超えたらエージェントが中間結果をユーザーに見せるように設計しなければならない。

## 2. ツール呼び出しコスト（Tool Call Cost）

エージェントがツールを呼び出すたびにコストが発生する。API呼び出しコスト、データベースクエリコスト、コンピューティングコスト。エージェントが一つの作業でツールを10回呼び出せば、そのコストが10倍になる。

問題はエージェントが「同じツールを繰り返し呼び出す」ケースだ。検索ツールで結果を受け取ったのに、その結果を理解できずに再検索。また再検索。API呼び出し上限を超えるか、コストが予想を跳ね超える。

実務ではツール呼び出し回数に上限を設けなければならない。「一つの作業で同じツールを最大3回まで」といったルールだ。上限を超えたらエージェントが中断し、人に通知する。コスト制御できないエージェントは使えない。

## 3. 権限境界（Permission Boundary）

エージェントが何をできて、何ができないのか。この境界が明確でないと、エージェントは「役に立とうとして」危険な行動をする。

読み取り権限だけ与えるべきところに書き込み権限を与えると、エージェントがデータを修正する。内部データだけ見るべきところに外部APIアクセスを与えると、エージェントが外部サービスにデータを送る。「役に立とうとして」した行動がセキュリティ事故になる。

実務では権限は**最小権限の原則**で設定する。エージェントに現在の作業に必要な権限だけ与え、作業が終わったら回収する。特にファイル削除、メール送信、決済といった行為はエージェントが直接できないようにブロックし、人の承認ステップを入れる。

## 4. 状態復旧（State Recovery）

エージェントが5ステップの作業中に3ステップで失敗したら、どうなるか。

良い設計：1〜2ステップの結果を保全し、3ステップから再開。
悪い設計：最初からやり直し。1〜2ステップを再実行してコストが2倍に。

エージェントが途中で失敗した時、どこまでやったかを記憶してそこから再開できなければならない。これを「状態復旧」と呼ぶ。状態復旧がないエージェントは、失敗するたびに最初から始まり、これは実務で使えない。

## 5. 実行環境（Execution Environment）

エージェントがコードを実行しなければならない時、そのコードがどこで実行されるか。サンドボックス（隔離された環境）で実行されれば安全だ。ユーザーの実際のマシンで実行されれば、エージェントがシステムファイルを触れる。

実務ではエージェントが実行するコードをサンドボックスで隔離し、ファイルシステムアクセスを制限し、ネットワークアクセスをホワイトリストで管理する。「エージェントが何を実行するかわからないから、とりあえず全部許可」は事故の原因だ。

## 実務適用：何を先に確認するのか

エージェントを導入または評価する時、この5つを順番に確認する。

1. **レイテンシ予算**: 一つの作業が終わるのにどれくらいかかるか？（測定）
2. **コスト**: 一つの作業でツールを何回呼び出すか？（測定）
3. **権限**: エージェントができることの範囲は？（文書化）
4. **復旧**: 失敗した時どこから再開するか？（テスト）
5. **環境**: コードがどこで実行されるか？（確認）

この中で一つでも「わからない」なら、それから解決しなければならない。賢いモデルを入れるのはその次だ。
